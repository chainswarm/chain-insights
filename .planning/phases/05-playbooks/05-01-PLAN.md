**src/playbooks/schema.ts** — Zod schemas (per D-01 playbook format decision):

```typescript
import * as z from 'zod'

export const ParamSpecSchema = z.object({
  name:     z.string(),
  type:     z.enum(['string', 'number', 'boolean']).default('string'),
  required: z.boolean().default(true),
  default:  z.string().optional(),
})

export const StepSchema = z.object({
  index:  z.number().int().positive(),
  label:  z.string(),
  tool:   z.string().min(1),
  params: z.record(z.string()),
})

export const PlaybookSchema = z.object({
  name:        z.string().min(1),
  description: z.string().default(''),
  version:     z.string().default('1.0.0'),
  params:      z.array(ParamSpecSchema).default([]),
  steps:       z.array(StepSchema),
})

export type PlaybookDefinition = z.infer<typeof PlaybookSchema>
export type StepDefinition     = z.infer<typeof StepSchema>
export type ParamSpec          = z.infer<typeof ParamSpecSchema>
```

**src/playbooks/parser.ts** — markdown → PlaybookDefinition (per D-01 format decision):

The frontmatter `params:` key is a SPECIAL CASE — `parseFrontmatter()` is flat-key only and silently drops YAML array lines. Handle `params:` by extracting its YAML block before calling `parseFrontmatter()`:

1. Split raw markdown at first `---` close fence, extract frontmatter block as a string.
2. Extract the `params:` multi-line block (lines after `params:` that begin with `  - `) manually, parse each entry as `name:type:required[:default]` OR use a simple per-line regex against YAML `- name: X` / `type: Y` / `required: Z` sub-keys.
3. Pass the remaining flat keys to `parseFrontmatter()`.

Step extraction from body:
- Split body on `/^## /m`, slice(1)
- For each section: extract `tool` from ` ```tool\n...\n``` ` block, extract `params` key=value pairs from ` ```params\n...\n``` ` block (one `key: value` per line)
- Apply `{{param}}` template substitution on all string values using: `text.replace(/\{\{(\w+)\}\}/g, (_, k) => params[k] ?? \`{{\${k}}}\`)`

Export: `export const PlaybookParser = { parse(markdown: string, resolvedParams: Record<string, string>): PlaybookDefinition }`

Validate the final object with `PlaybookSchema.parse()` — this provides all Zod errors.

**src/playbooks/resolver.ts** — name → file path (per D-01 name resolution decision):

```typescript
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import { access, readdir } from 'node:fs/promises'
import os from 'node:os'

const __dirname = path.dirname(fileURLToPath(import.meta.url))
const BUILTIN_DIR = path.join(__dirname) // built-ins live alongside resolver in dist/playbooks/

function userDir(): string {
  return path.join(os.homedir(), '.chain-insights', 'playbooks')
}

export async function resolvePlaybook(name: string): Promise<string> {
  // Security: sanitize name to prevent path traversal (per security threat T-05-01)
  const safeName = name.replace(/[^a-z0-9_-]/gi, '')
  if (!safeName) throw new Error(`Invalid playbook name: ${name}`)

  const userPath = path.join(userDir(), `${safeName}.md`)
  const builtinPath = path.join(BUILTIN_DIR, `${safeName}.md`)

  try { await access(userPath); return userPath } catch { /* fall through */ }
  try { await access(builtinPath); return builtinPath } catch {
    throw new Error(`Playbook not found: "${safeName}". Run \`chain-insights playbook list\` to see available playbooks.`)
  }
}

export async function listPlaybooks(): Promise<Array<{ name: string; source: 'builtin' | 'user' }>>
```

**src/playbooks/runner.ts** — orchestration only, no infrastructure logic (per architectural responsibility map):

```typescript
export interface RunnerOptions {
  caseId?:    string    // attach to existing case; omit for quick-case auto-creation
  from?:      number    // 1-based step to resume from (default: 1)
  dryRun?:    boolean   // print steps, no MCP calls
  params?:    Record<string, string>
}

export const PlaybookRunner = {
  async run(playbook: PlaybookDefinition, opts: RunnerOptions): Promise<void>
}
```

Implementation rules:

1. **initSchema first** — call `initSchema(conn)` once before any case operations (per pitfall 3). Pattern from cli.ts: `const conn = await getDb(); await initSchema(conn); conn.closeSync()`.

2. **Case resolution** — if `opts.caseId` provided, call `CaseStore.get(opts.caseId)`. Otherwise auto-create: `CaseStore.create({ name: \`quick-${playbook.name}-${Date.now()}\`, tags: ['quick', 'playbook', playbook.name], description: \`Auto-created for one-off playbook run: ${playbook.name}\` })`.

3. **Dry-run** — if `opts.dryRun`, print each step as `Step N/M: <tool> (params: {...})`, print estimated cost as "Cost: unknown (MCP pricing not available without live connection)", return early.

4. **Single MCP connection** — open ONE `Client` + `StreamableHTTPClientTransport` before the step loop; close in `finally`. Do NOT open per-step (pitfall 2).

5. **Step loop** — iterate steps starting at `startIndex = (opts.from ?? 1) - 1` (pitfall 6). For each step:
   - Print `Step N/M: <step.label>...`
   - Call `callTool` with 3-retry logic on timeout (AbortError / `code === 'ECONNRESET'`). Sleep 1s between retries.
   - On x402 payment failure (error message includes 'insufficient' or HTTP 402): if `process.stdin.isTTY`, prompt via readline `(retry/skip/abort)`, handle response; if not TTY, abort with clear message.
   - On other MCP error: print `Step N failed: <error.message>. Completed: steps 1..(N-1). Run with --from ${step.index} to resume.` and throw.
   - On success: call `EvidenceStore.append(caseId, { source: step.tool, content: result, queryParams: JSON.stringify(step.params) })`.
   - Print `✓ (<result length> chars stored)`.

6. **Auto-viz** (trace-funds only) — after all steps complete, if `playbook.name === 'trace-funds'`: wrap `await generateVisualization({ caseId })` in try/catch; on error print `No transaction data to visualize.` (per pitfall 4).

7. **Final summary** — print `Playbook complete. Case: <caseId>. Evidence: <N> entries.`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arg → playbook name | User-supplied name used to construct file paths |
| Playbook file → step.tool | Tool name from markdown content passed to MCP callTool |
| Playbook file → step.params | Param values from markdown and CLI injected into MCP arguments |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | resolver.ts — name → file path | mitigate | Sanitize name before path construction: `name.replace(/[^a-z0-9_-]/gi, '')` — prevents `../../etc/passwd` traversal |
| T-05-02 | Tampering | runner.ts — step.tool → callTool | mitigate | Validate tool name is non-empty string; Zod StepSchema enforces `z.string().min(1)`. Future: cross-check against MCP schema cache (loadSchema) before calling |
| T-05-03 | Tampering | parser.ts — {{param}} substitution | accept | Params are passed as JSON arguments to MCP tool, never interpolated into shell commands. No shell injection risk. Sanitize only for display output. |
| T-05-04 | Denial of Service | runner.ts — unbounded retry loop | mitigate | Hard cap of 3 retries on timeout with 1s sleep. x402 payment failures require explicit user action (retry/skip/abort). |
| T-05-05 | Information Disclosure | runner.ts — evidence files | accept | Evidence written to `~/.chain-insights/cases/` with mode inherited from EvidenceStore (0o600). No additional mitigation needed at this scope. |
</threat_model>
